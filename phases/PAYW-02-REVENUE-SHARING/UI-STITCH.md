# PAYW-02 UI design and runtime acceptance

Stitch MCP is required before implementing the new admin/seller surface. Inspect existing navigation, tokens and shared Admin primitives first. Preserve blue/navy/white and restrained semantic colours; use component-owned styles.

Admin surface: retail fee, versioned terms, membership rules/weights, preview of matched courses and dilution, immediate/delayed activation with conditional positive-day input, pending changes/cancellation and revenue report.

Seller surface: own courses, terms and matching plans before acceptance, current/upcoming membership inclusion, explicit no-match state, opt-out, notifications and pending/recognised/refund report. No payout button or withdrawable-balance claim.

Record Stitch artifact references and actual browser results in delivery evidence. Required widths: 320, 375, 390, 412, 768, 1024, 1440 px. This file does not claim design/runtime verification has happened.
