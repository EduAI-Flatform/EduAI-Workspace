## Contract and implementation order

1. Add an immutable activity receipt tied to canonical source identity and an approved policy revision. The first native adapter reads server-verified course completion; clients must never submit an amount or authoritative completion claim. Extend to additional registered adapters only with equivalent verified source facts. School-specific adapters follow the future partner contract, not invented endpoints.
2. Freeze policy selection at the event occurrence/effective date. Apply the Admin-configured award, UTC-day cap and clamped calendar-month expiry. Policy changes cannot recompute historic grants. Record zero awards/skipped events explicitly as receipts, without creating fake zero-value ledger transactions. Repeated workers/retries must never award the same source again, even after a policy revision.
3. Use additive persistence: an append-only activity receipt with unique `(event_type, source_id)` and an append-only expiry-settlement receipt with unique earned-ledger ID. Both retain foreign keys and policy/source provenance. Expiry receipts may record zero remaining points when fully spent so batch processing cannot starve on repeatedly rediscovered fully-spent grants. Positive settlements link the canonical ledger posting.
4. Serialize all point mutations on the same user lock used by the existing redemption/adjustment services. Settle due expiry before spend/adjustment/refund decisions and atomically post receipts/ledger/audit. A read-only wallet projection must exclude due unspent points without inventing ledger history. Preserve historical paid course grants, wallet money and the existing non-cash ledger; no parallel points wallet.
5. Refund integration must retain original grant validity for native activity points, rather than silently turning expiring points into immortal refund credit. Legacy refund behavior remains compatible. Add dedicated tests for mixed legacy/native credits, partial spends, refunds at/after expiry, exact cutoff, disabled policies, concurrent workers/redemption and retry after rollback.
6. Add a bounded background processor using existing Nest lifecycle/worker conventions. Process completed events and due expiry independently; disabling future accrual must not stop previously granted points from expiring. Do not expose a generic public award endpoint. Unknown event kinds remain blocked. Point defaults remain disabled until an Admin-approved, effective supported policy exists.
7. Add a reviewed additive migration and exact runtime permission matrix (append-only SELECT/INSERT, no broad DELETE/UPDATE). Extend the production migration runner with independently pinned artifacts/explicit approval, preserve the existing seven GDS and financial migration history, require private backup/pre/postflight, and verify the actual restricted Prisma role in disposable PostgreSQL before release. Existing authorization persists, but automatic tool-review rejections must be handled directly without alternative-tool bypass.
8. Complete Admin VI/EN supported-rule choices/readiness and impact/provenance visibility on existing reviewed surfaces. Run source tests, real PostgreSQL concurrency/invariants and affected browser/responsive checks; review, PR/CI, controlled deployment, real verification and merged-branch cleanup. Do not mark the feature or overall plan done before those gates pass.
