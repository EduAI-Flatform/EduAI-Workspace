# Video progress correctness and persistence

Status: scoped fix released and verified. Overall GDS plan remains VERIFYING. The continuation found two actual client/server integration defects while checking saved progress.

## Reproduced defects and fix

Native media timestamps such as 12.345678 were forwarded unchanged, while the existing backend DTO accepts at most two decimal places. Actual backend validation rejected all three raw timestamp fields and accepted the normalized sample. Two new frontend wire-contract tests failed before the fix. The client now rounds finite nonnegative media seconds to two decimals and omits unavailable NaN/Infinity values. Negative values retain server validation, document progress stays unchanged, and caller input is not mutated.

The progress debounce also restarted on every `timeupdate`, preventing a checkpoint during continuous playback. This conflicted with the backend's existing five-second advancement window. A real 6.5-second Chromium clip reproduced zero outgoing checkpoints while playing. The page now uses a four-second checkpoint timer that is not restarted by each event, resets after flush, and is cleared/reset on lesson cleanup. The long-clip regression verifies a bounded checkpoint while the video is still playing, a trusted native end event, replay, one quiz invitation and no automatically created attempt. An old five-second replay assertion initially timed out after extending the clip; its wait now accounts for the actual clip duration. No access/completion rule or schema was relaxed.
